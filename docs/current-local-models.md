# Current local-model qualification

On the audited RTX 3060 (12 GB VRAM) and 32 GB RAM workstation, the installed Ollama 0.40.2 runtime matches the [official current release](https://github.com/ollama/ollama/releases/tag/v0.40.2). Model tags still need separate checking: the July `gemma4:latest` manifest differed from the registry, while `qwen2.5:7b` matched its older model-family tag.

The October 10, 2026 audit installed [Qwen 3.5 9B](https://ollama.com/library/qwen3.5:9b), [Gemma 4 12B](https://ollama.com/library/gemma4:12b), and refreshed `gemma4:latest`. It retained the previous Gemma tag as `gemma4:archive-20260708` for comparison. Explicit size tags help avoid accidentally choosing a larger variant when `latest` changes.

Both candidate models were tested on a coherent non-final setup, a real paper-ledger contradiction, and the saved Chapter 2. These probes distinguish scope judgment and contradiction detection from novel completion. Their raw responses and the before/after model digests are saved in the workstation's ignored `artifacts/model-audit-20261010/` directory.

Thinking-capable models may use their response allowance on reasoning before emitting any final answer. A live Qwen probe exhausted 64 tokens with an empty answer under its default thinking mode, while `think=false` returned the requested JSON in seven tokens. A later live editorial test with `think=true` exhausted 8,192 tokens with no valid final review JSON. The application therefore defaults to `OLLAMA_THINK=false`; `OLLAMA_THINK=true` enables thinking explicitly. Reasoning text is separate from manuscript text. See [Ollama thinking controls](https://docs.ollama.com/capabilities/thinking).

For a fresh isolated pipeline test:

```powershell
ollama pull qwen3.5:9b
ollama pull gemma4:12b
docker compose -f docker-compose.yml -f docker-compose.local.yml exec -T -e OLLAMA_CONTINUITY_THINK=true -e OLLAMA_CONTINUITY_TEMPERATURE=1.0 -e OLLAMA_ADJUDICATION_THINK=true -e OLLAMA_ADJUDICATION_TEMPERATURE=1.0 worker python -m novel_generator.services.local_verification --model qwen3.5:9b --review-model gemma4:12b --revision-model gemma4:12b --base-url http://host.docker.internal:11434 --chapters 2 --words-per-chapter 700 --output-dir /app/artifacts/current-model-e2e
```

Use a new output directory for each qualification. Check that `report.json` contains both `pipeline_complete: true` and `autonomous_checks_passed: true`, inspect the manuscript and final ending, and verify the exported Markdown and DOCX files. A miniature manuscript confirms the pipeline for that sample; a whole novel still needs its own final checks and exports. Use `--project-file` with a ProjectCreate JSON to test other premises, genres, and novel-length targets.

Provider Settings are persisted in the database. Update the default model and the run's stage routes there as well as any environment defaults. Keep the Ollama URL at `http://host.docker.internal:11434` for Docker deployment. A model update alone does not erase previous repair history or restart a failed run.

The live miniature test also exposed a compression stop: a useful 147-word revision exceeded a passage's 122-word limit after two attempts. Compression now preserves the shortest nonempty candidate that reduces the source, debits its actual count from subsequent passages, and returns the assembled chapter for normal length and editorial checks. If the allocation is exhausted, the unedited narrative suffix is preserved. Empty or unchanged responses still fail; no sentences are clipped and missing the passage target never certifies the manuscript.

When an older model has exhausted a chapter's strategies, a new-model continuation can use the application's source-run and resume-from-chapter controls. This preserves completed predecessor chapters, the story contract, and the original run's entire history while regenerating the failed chapter with the new model. It is distinct from repeatedly resetting a failed run's counters.

Use stage routes to test model roles separately. On a live compressed passage, Qwen 3.5 9B proposed unsupported scene objections, while Gemma 4 12B identified an employment-timeline contradiction and incomplete technical phrasing. An explicit `autonomous_revision` route now applies to coordinated repairs and escalated chapter rewrites too; without that override, those demanding repairs default to the drafting route. Selecting a stronger editor must not silently send its repair work back to a different model.

Editorial reviews distinguish required corrections (`issues`) from evidence-grounded aesthetic advice (`optional_suggestions`). Optional wording, imagery, or subtext preferences do not fail checks or trigger another repair. Contradictions, missing required outcomes, broken grammar, and materially redundant passages still require correction. Failed checks cannot be justified solely by optional suggestions. Unsupported or malformed optional advice is discarded and logged without invalidating the required checks; invalid evidence for a required repair still rejects the review. This prevents a paraphrased quotation in a style suggestion from stopping an otherwise accepted manuscript.

Final qualification reviews the complete actual prose of every adjacent chapter pair, in addition to individual chapters and the whole-book map. Opening and ending excerpts can miss a date, identity, or custody contradiction elsewhere in a chapter. The pair audit focuses on factual continuity, identities, and causes; separate chapter and book audits retain prose and closure requirements. Pair reviews retain source paragraph references and strict required-defect validation, and run again when either chapter or their controls change. They do not certify that all distant narrative facts have been detected.

On the live control tests, a broad pair-review prompt missed a signing-date contradiction, and a focused prompt without thinking falsely rejected a coherent elapsed-time change. Gemma 4 12B with thinking and temperature 1.0 accepted the coherent pair and correctly rejected the deliberate contradiction, returning validated final JSON in approximately 32 and 23 seconds. This temperature follows [Gemma's published sampling guidance](https://ollama.com/library/gemma4:12b). Set `OLLAMA_CONTINUITY_THINK=true` and `OLLAMA_CONTINUITY_TEMPERATURE=1.0` for that tested route. These optional overrides apply only to Ollama chapter-pair reviews; leave them unset to inherit normal controls. Drafting and other structured stages retain `OLLAMA_THINK=false` and their ordinary sampling.

Longer thinking reviews can still exhaust their token allowance before emitting final JSON. When a structured response explicitly reports a length stop with reasoning but no final answer, the client makes one bounded final-verdict request with thinking disabled. Provisional reasoning is supplied as a document to verify against the complete original source. Only these derived notes may be excerpted for context headroom; source prose remains intact. Normal schema, chapter coverage, and evidence validation still apply, and validation corrections retain the source without restarting thinking. Provider telemetry records this finalization separately from transport failures.

Repeated whole-book diagnoses are independently verified before another repair, just as repeated chapter diagnoses are. Older QA or ending-debt findings can become stale after revisions. The verifier checks the current final prose and distinguishes an absent promised outcome from a request to describe the same outcome differently. A confirmed defect remains blocking; previous repairs never grant automatic acceptance.

The verification pass receives allegations and current source, without the initial review's answer flags, optional preferences, or proposed repairs. It also omits old QA and ending-debt diagnoses. In the live miniature test, the earlier pass copied a false allegation that returning to a previous location was impossible. The revised pass searches intervening source for counterevidence and also verifies repeated pair diagnoses. Optional `OLLAMA_ADJUDICATION_THINK=true` and `OLLAMA_ADJUDICATION_TEMPERATURE=1.0` apply only to this verification pass. With Gemma 4 12B, three live controls accepted normal travel and a depicted aftermath while retaining a real signing-date contradiction, in approximately 14, 17, and 38 seconds. These controls do not establish whole-novel quality.

Whole-book length corrections adjust chapters outside the requested repair band in the needed direction. An overlong book does not request changes to a chapter already near its own target, and a short book does not expand chapters already at that target. This prevents unchanged, compliant chapters from stopping the run while another chapter still needs compression or expansion. The assembled manuscript must still satisfy the original chapter ranges and total word-count checks.

Its tested non-thinking configuration missed the deliberate contradiction, so it was not selected for production. The longer manuscript probe was canceled after that failed control.
